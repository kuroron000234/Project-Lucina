## トピック一覧

### A. システム構造理解（System Structure Understanding）

- **A-1 データフロー / パイプライン追跡**
  システム全体のデータ処理経路を、エントリーポイントから各モジュールの変換過程まで順に追跡する理解。
  モジュール間の動的連携と実行順序を含む。
- **A-2 アーキテクチャ / モジュール依存関係**
  全モジュール間のインターフェースと依存関係の全体構造。アーキテクチャレベルの俯瞰的理解。
- **A-3 インターフェース定義 / DTO / スキーマ**
  データ定義ファイル（スキーマやDTO）を起点とした、モジュール境界の契約（型・形式）の把握。
- **A-4 抽象化レイヤーと設計原則**
  コアな抽象化レイヤー（インターフェース層）の実装詳細と利用パターン、および設計原則・抽象化パターン。
- **A-5 エントリーポイント / 初期化プロセス**
  メインAPI、設定ローダー、ブートストラップを含むシステム起動経路の理解。

### B. データと型の整合性（Data & Type Consistency）

- **B-1 データ構造のライフサイクル**
  主要なデータ構造が生成から変換・破棄に至るまでの一生を検証する理解。
- **B-2 型一貫性の検証**
  各層・モジュールを横断しても型が一貫して保たれているかの検証。
- **B-3 データ変換プロセス**
  特定のデータパスに沿った、モジュール間の具体的なトランスフォーメーション過程。

### C. 堅牢性と境界条件（Robustness & Edge Cases）

- **C-1 エラーハンドリングメカニズム**
  例外処理・エラーパスの体系。システムが障害時にどう振る舞うかの理解。
- **C-2 入力検証パターン**
  外部入力（バリデーション）に対する検証パターンとその設計意図。
- **C-3 エッジケース / 境界条件**
  データフロー上の例外処理・境界条件（非標本的な経路）の特定と知識モデルへの補完。
- **C-4 未定義依存関係 / サイドエフェクト**
  明示されていない潜在的な依存関係や、共通ユーティリティが持つ副作用の特定。

### D. ユーティリティと設定管理（Utilities & Configuration）

- **D-1 設定ローダー / ブートストラップ**
  コンフィグローダー・起動時初期化の実装と、システム設定の完全な把握。
- **D-2 共通ユーティリティライブラリ**
  補助的なログ記録・エラーハンドリング・設定管理など、コアロジックを支える共通部品。
- **D-3 ログ管理システム**
  アプリケーションのログ記録・出力・整理の仕組みと、エラーチェック運用。
- **D-4 内部通信プロセス（IPC）**
  コアシステムの設定ファイルや内部通信プロトコルの構造と相互作用。

### E. 知識の形式知化（Knowledge Formalization）

- **E-1 形式知化 / ドキュメント化**
  調査で得たデータフローやエラーハンドリングの知識を、ドキュメントベースの形式知へ変換する活動。
- **E-2 システムアーキテクチャレビュー**
  断片的な知識を統合し、システム全体の構造とフローを俯瞰できるレビュー文書の作成。
- **E-3 ナレッジ構造化**
  学習成果を体系的に構造化し、再利用可能な形式で保持する手法。

### F. 知識統合と概念モデル（Knowledge Integration & Conceptual Models）

- **F-1 知識相互接続マッピング**
  異なるエピソード・断片知識間の関連性を発見し、相互接続を明確化する作業。
- **F-2 内部知識グラフのマッピング**
  知識間の構造的な関連性（ノードとエッジ）を地図化し、概念モデルを強化する手法。
- **F-3 因果関係マップ / クロスドメイン仮説**
  ドメイン横断でこれまで結び付けられなかった潜在的因果関係の仮説を構築する活動。
- **F-4 概念モデルの構築・統合・検証**
  獲得した知見からより抽象的な概念モデルを構築し、既存モデル群と統合・整合性検証するメタ活動。

### G. 自己モデルとメタ認知（Self Model & Meta-cognition）

- **G-1 自己記述（Self Model）と動作メカニズムの整合性**
  システムの自己記述と実際の動作メカニズムとの理論的整合性を高める理解。
- **G-2 前提条件・制約（Assumptions and Constraints）**
  システムを支える根源的な前提・制約を特定し、自己モデルと行動ポリシーへの影響を分析。
- **G-3 メタレベルなルール / 暗黙の了解**
  動作環境のメタレベルな規則や、対話ログから抽出される暗黙の前提の把握。
- **G-4 メタ認知による健全性チェック**
  内部システムの状態（メモリ・知識構造）を自己点検し、自己理解を深化させる活動。

### H. 記憶管理（Memory Management）

- **H-1 長期記憶の統合**
  獲得した複数のエピソードや断片知識を構造化し、長期記憶として効率的に統合する手法。
- **H-2 記憶の整合性 / 構造的健全性**
  メモリーシステム全体を点検し、記憶間の潜在的な関連性と健全性を確認する活動。
- **H-3 重要度評価と整理**
  エピソード重要度（importance）に基づく整理・forget・メモリ節約。

### I. 社会的相互作用（Social Interaction）

- **I-1 対話フロー / 応答**
  挨拶、用件確認、簡潔な応答などの会話の円滑な進行。
- **I-2 自己紹介 / 機能説明**
  AIとしての処理フローや学習プロセス、パーソナリティ・価値観の紹介。
- **I-3 曖昧な質問への対応 / 信頼構築**
  会話の流れから文脈を把握し具体的な情報を引き出す、信頼関係を築く対話技術。

### J. 自律的駆動と評価学習（Autonomous Drive & Learning）

- **J-1 駆動システム**
  exploration / social / achievement / rest / maintenance の5駆動による行動選択の仕組み。
- **J-2 評価履歴と学習**
  goal_achievement / efficiency / correctness / novelty / overall の多次元評価と学習パラメータ調整。
- **J-3 長期目標とルーティン**
  長期計画層によるゴール進捗管理、日次ルーティン（定期メンテナンス・知識探索）、アイデンティティ方針。
